# O05a・真实 PostgreSQL / Redis 故障门禁运行说明

O05a 只交付测试基础设施与脱敏 evidence 门禁。它不代表 Redis 进程重启、网络分区或 2–3 个真实应用实例演练已经通过；这些属于 O05b 测试环境演练。

## CI 门禁

`.github/workflows/enterprise-failure-drills.yml` 使用当前 Job 独享的 ParadeDB/PostgreSQL 与 Redis service containers，并在其中创建随机数据库和 Redis DB。门禁精确运行：

- 5 个真实 PostgreSQL 多连接 suites，共 19 assertions；
- Identity Provider convergence 的 4 assertions；
- 通过 `testNamePattern` 精确选择的 startup advisory-lock crash assertion；
- 通过 `testNamePattern` 精确选择的真实 Redis Version Key 丢失后数据库重建 assertion。

任何报告缺失、assertion 数不符、全部 skip、存在 failed/skipped assertion、清理失败或脱敏扫描失败都会让 runner 非零退出。上传物仅为 `.records/enterprise-failure-drills/<run-id>` 下的汇总、分类、依赖短版本与 SHA-256；Vitest 原始 JSON 不上传。

## 本地运行

先准备一次性的本地 PostgreSQL 数据库和独立 Redis DB，再设置以下测试变量；不要使用生产凭据或阶段 0 共用数据库：

```bash
export TEST_SERVER_DB=1
export DATABASE_TEST_URL='postgresql://postgres:postgres@127.0.0.1:5432/<random-database>'
export TEST_REDIS_URL='redis://127.0.0.1:6379/<isolated-db-number>'
```

CI 文件中的各组 `bunx vitest run` 命令是本地精确门禁命令。保留相同的 file selectors、`--fileParallelism=false --maxWorkers=1`、两个 `--testNamePattern` 和 JSON 文件名，然后运行：

```bash
bun scripts/enterprise/failure-drills/index.ts collect \
  --bun-version "$(bun --version)" \
  --cleanup-result passed \
  --git-sha "$(git rev-parse HEAD)" \
  --node-version "$(node --version | sed 's/^v//')" \
  --output-dir ".records/enterprise-failure-drills/local-$(date +%s)" \
  --postgres-version '<server-major.minor>' \
  --redis-version '<server-major.minor.patch>' \
  --reports-dir '<raw-vitest-json-directory>'
```

只有真实服务已运行、全部报告均满足预期且资源清理成功时，才能传入 `--cleanup-result passed`。缺少 Docker/PostgreSQL/Redis 时只能报告静态校验结果，不能把本地未执行写成演练通过。
