## 2. 身份与授权体系决策

1. **登录（M11 完整实施）**：管理后台数据库化配置 OIDC Provider（Discovery、测试、发布、重启激活、Last Known Good 全流程），不走环境变量直配的简化路线。首选对接企业 Authentik，登录页提供“使用工作账号登录”入口。
2. **身份透传（与 EasyTrade 一致）**：scopes 为 `openid profile email dingtalk`；显示名取 `name`/`preferred_username`；保存 `dingtalk_user_id`、`dingtalk_title`、头像；登录即透传钉钉用户名。
3. **平台管理员授权（EasyAuth 同步到内建 RBAC）**：AIHub 注册为 EasyAuth 应用（app_key=`aihub`，暴露 `/.well-known/easyauth-app.json` 描述符）；平台角色作为权限目录发布到 EasyAuth；授予走 EasyAuth 门户 + 钉钉审批；AIHub 在用户登录时与定时任务中同步 AccessGrant 写入内建 RBAC 表；运行时仍以内建 RBAC（M02）为唯一授权执行点。
4. **用户准入（需要 EasyAuth 准入）**：员工经 Authentik 登录后默认无权限，需 EasyAuth 授予基础访问权限（如 `aihub.access`）后才能使用；未授予者登录后进入“申请权限”引导页，跳转 EasyAuth 门户走钉钉审批。
5. **Break-glass**：本地超级管理员（G-04/G-05）不依赖 Authentik/EasyAuth，用于 IdP 或授权服务故障时的应急管理。

## 3. 功能规则决策（均已确认）

1. 用户可以在管理员发布的模型范围内自由选择，但不能创建或修改 Provider/Model 定义。
2. 平台 Agent 分为 `mandatory`、`default`、`optional`；Mandatory 不可隐藏，Optional 可由用户隐藏。
3. 默认 Lobe AI 的内部键保持 `inbox`，用户可见名称由 Branding/平台 Agent 决定。
4. 平台默认设置允许用户覆盖；锁定设置由服务端强制；隐藏只影响可见性，不能替代锁定。
5. Connector 默认采用每用户 OAuth；共享服务账号只对经安全审批的只读或低风险系统开放。
6. 子管理员首版使用固定角色包，不开放任意自定义权限组合；后续再评估自定义角色。
7. 用户模拟登录首版不做；需要排障时使用审计、安全诊断和受控数据导出。

## 4. 品牌决策

1. 正式平台名称为 **AIHub**（文档中原示例名 FreeHub 以此为准）。
