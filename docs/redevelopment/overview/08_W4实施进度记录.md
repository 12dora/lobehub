## 3. Secret、发布与权限闭环

- Provider 凭据按 runtime 类型校验，支持多字段 Key Vault、无 Key Provider 与明确环境应急覆盖；客户端只获取 configured/fingerprint 等非敏感状态。
- config/settings、Endpoint query、Provider/Model 自由文本、reason/comment、连接错误和本地 raw draft 均有 Secret / 凭据 URL 对抗门禁；`signature`/`sig`/`X-Amz-Signature` 变体被拒绝，普通业务 signature 不误伤。
- Publish、Rollback、Archive 与 M05 Settings 发布共用 PostgreSQL advisory transaction lock；按当前 Published 到目标 Revision 的 enabled-model 差集在锁内重查依赖。
- Provider 详情最小权限为 `platform_ai_provider:read`；写操作分别校验 create/update/delete/test/publish。Model-only 管理不附加 Provider update 权限。

## 4. Runtime 与 UI 一致性

- Builtin Provider 固定使用 provider key，仅 custom Provider 使用 `sdkType`/OpenAI 默认；Test、Publish、Runtime、Memory 和 Persona 共用规范化 Execution Config。
- Readiness 自身要求至少一个 enabled chat model；flag-off、unsupported-only、env-only、Secret 和污染历史 Revision 均有回归。
- Published Catalog 仅安全公开 `config.deploymentName`，Endpoint、Secret、ciphertext 不进入公开响应。普通用户 Picker 仅消费同一个 Secret-free runtime state。
- Admin UI 支持结构化凭据、零 Model Provider 的服务端搜索 / 游标选择器、只读 auditor 和异步 write epoch；旧 modal 不会在刷新成功后复活并提交旧 CAS。
