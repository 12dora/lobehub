## 2. 编排工作流（历史约定；后续非本计划实现波仍可沿用）

**每模块一个 git worktree，实现子代理高强度实施 → 编排 agent 派出的独立审核子代理审核 → REWORK 交回原实现子代理，同一 reviewer 复核至 PASS → 合入 main。并行最多 2 个实现子代理。审核子代理不是实现代理自审，也不由实现代理派出。**

W4–W8 按用户指示由编排 agent 派出的实现子代理接手编码；独立 reviewer、原实现代理返工、同 reviewer 复核至 PASS 与分批提交规则未改变。后续若恢复 Grok，`--reasoning-effort high` 仍为硬性要求。

### 2.1 起一个模块（运维补丁 / 非本计划新波次时）

```bash
export PATH=/usr/local/bin:/opt/homebrew/bin:/usr/bin:/bin:/usr/sbin:/sbin:$HOME/.bun/bin
git worktree add /Users/konata/code/AIHub-worktrees/<mXX> -b feat/<mXX>-<name> main
cp <repo>/.env.development /Users/konata/code/AIHub-worktrees/<mXX>/   # gitignored,含 dev 端口与 Authentik 配置
cd /Users/konata/code/AIHub-worktrees/<mXX> && pnpm install --prefer-offline
# 写一份 prompt-<mXX>.md(见 §2.4 要点),用新 uuid 起 headless grok:
grok --prompt-file <prompt> -s $(uuidgen|tr A-Z a-z) --reasoning-effort high --r-approve --no-plan --check
```

- **`--reasoning-effort high` 是硬性要求**(用户明确指定)。
- grok CLI:`/opt/homebrew/bin/grok`;headless 单轮用 `-p/--prompt-file`,`--check` 追加自校验循环。

### 2.2 返工 (保留 grok 会话上下文)

```bash
grok --resume <同一 uuid> --reasoning-effort high --always-approve --no-plan --check --prompt-file <rework-<mXX>-rN.md>
```

### 2.3 审核 (编排 agent 派出的独立子代理，不是 Grok)

- 由当前编排 agent 使用子代理工具派出 general-purpose 或专职审核 agent，范围 `main...HEAD`,**只读 + 跑测试，不改代码**；不得让 Grok 派审核或用 Grok 自检替代。
- 审核依据：模块 `plan/Mxx*.md` 逐节 DoD + `list/04_权限矩阵.md` + `list/06_验收矩阵.md` + `AGENTS.md`; 安全项 (Secret 泄露 / Flag 默认关 / 越权 / SSRF) 必查；实证验证 (自建对抗测试、探针、迁移快照比对), 不采信 grok 自述。
- 输出首行 `VERDICT: PASS` 或 `VERDICT: REWORK` + 编号问题清单 (blocker/major/minor + 文件：行 + 给 grok 的修复指令)。
- 复核用 SendMessage 续同一审核 agent (保留上轮上下文)。
- **教训:grok 每个模块都自报 PASS, 但 W1 四个模块首轮审核全部 REWORK**—— 自检不可信，审核不能省。

## 5. 仓库坑 (踩过的，务必知道)

1. **blob:none 部分克隆**:`git commit`/`git worktree add` 会触发向 GitHub 惰性拉取对象，慢属正常，不是死锁。
2. **主仓 main 提交必须 `--no-verify`**:`.githooks/pre-commit` 在 main 分支跑全量 type-check (慢), 且 lint-staged 的 remark/prettier 会重写 `.md` 破坏 `MANIFEST.md` 的 sha256。
3. **改了 `docs/redevelopment/` 任何文件后必须刷新 MANIFEST**:`MANIFEST.md` 是 `| 路径 | 字节 | sha256 |` 表，用 legacy 目录名 (overview→`00_实施总览/`、plan→`01_实施模块/`、list→`02_工程清单/`、ref→`03_参考资料/`)。用 python 重算改动文件的 len+sha256 回填对应行；并校验**全部**条目与磁盘映射一致。
4. **shell PATH 偶发丢失**: 命令开头统一 `export PATH=/usr/local/bin:/opt/homebrew/bin:/usr/bin:/bin:/usr/sbin:/sbin:$HOME/.bun/bin`。
5. **drizzle 迁移生成陷阱**:`drizzle-kit generate` 可能因既有表索引 where 大小写漂移 (`is null`↔`IS NULL`) 误产生 DROP/CREATE INDEX—— 生成后必须 diff 确认 SQL 只含本模块新对象；`.prettierignore` 已忽略 `migrations/meta/` 防重排。**`_journal.json` 条目数必须 == `meta/*_snapshot.json` 数**(当前 137/137，latest `0136`；缺 snapshot 会导致下次 generate 炸库)。
6. **dev 基础设施**:`docker-compose/dev/docker-compose.phase0.yml`(项目名 aihub-dev,postgres:5433/redis:6380/rustfs:9010),`bun run db:migrate` 验证迁移；真实登录见 03 文档 (env 直配 Authentik, Generic OAuth 回调为 `/api/auth/oauth2/callback/authentik`)。
7. **证据语义**：`passed`（生产）仅在 production-authorized + 钉死 trust policy 与七门禁签名证据时可达；`unverified` / harness / CI 绿 **不是** 生产通过。见 `14_Q06…`。
