## 3. Skill 运行时与审核闭环

- 平台 Skill 版本在发布后不可变，历史 Agent/operation 依赖按精确版本和 checksum 解析；归档不破坏已固定历史。
- 分发语义固化 mandatory/default/optional 与 pinned/auto/disabled；受管时忽略个人同 key 定义，Flag 关闭时不产生额外策略 IO。
- 执行工作区只物化 validator 已验证的 inline text，用 operation id + 完整 checksum 隔离，目录 / 文件权限为 0700/0600，并有 finally cleanup 与 TTL 回收；个人 ZIP、由 skill key 派生路径和 Web 进程 spawn 不会进入该路径。
- 独立审核首轮未采信实现代理自检，实际触发多轮 REWORK：收紧资源 / URI / 控制指令校验绕过、不可变版本投影、本地草稿 / 旧 CAS、精确 operation proof、跨运行时工作区与多实例缓存失效；原代理修正后复核 PASS。

## 4. Connector 安全、OAuth 与 UI 闭环

- Connector 定义、平台 Secret 版本、用户 Binding 完全分层；`none` / `shared_service_account` / `per_user_oauth` 三种模式具有独立服务端解析路径，客户端仅看 configured/fingerprint 等非敏感状态。
- 所有 Discovery/Test/Published Runtime/旧 MCP 管道共用动态版本化出站策略；G-07 默认 `allow-private`，可收紧为 allowlist，Metadata 即使出现在 allowlist 也永久禁止。
- OAuth callback 只信任服务端 state/attempt；UI 轮询绑定 authorization attempt，不用“Connector 已连接”代替本次尝试成功。Token 刷新使用租约 / CAS，撤销和失败只影响对应用户 Binding。
- Tool 执行权威绑定平台 Revision、Agent identity、User Binding、persisted tool call 与审批；平台 deny 无法被 Agent/用户重新开启，高风险 Tool 在用户侧显示风险与确认要求。
- 独立迁移审核首轮 REWORK 发现 orphan user FK 升级、遗留 Endpoint 回填、PostgreSQL 微秒 Date CAS、在线 DDL 和伪迁移 fixture；修正后以 NOT VALID/VALIDATE、遗留行 `migration_required`、毫秒截断、concurrent predeploy 与真 PostgreSQL 双跑回归闭环。
- 管理 API 首轮 REWORK 发现 OAuth 之外也急切依赖 `APP_URL`、出站策略不能运行时收紧、factory/dependency 失败缺审计；修正后改为 OAuth-only 懒解析 redirect、逐请求动态策略与结构化失败审计。
- UI / 跨层复核继续截出未保存 Secret、凭据模式切换、草稿态危险操作、settings 路由旁路和 OAuth 状态错绑等问题；原 UI 代理修正后由同 reviewer 复核 PASS。
