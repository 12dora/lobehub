## 2. M11 交付闭环

- `platform_identity_providers`、Secret、revision、测试 attempt、启动 instance/restart request 等对象均通过独立迁移与 repository 约束落地；发布、回滚和读取使用 revision/draft token/共享锁，Secret 不进入公开契约、审计或日志。
- Admin 页面提供 Basic、Discovery、Client、Claims、Policy、Test、Publish 全流程；发布后显示 pending restart，受控重启要求确认、reason、服务端 reauth 与审计，旧实例通过心跳自然转为 stale。
- 启动快照只接受校验后的 discovery/token/JWKS 元数据，真实 token/discovery 请求继续走 public-only `SafeOutboundHttpClient`；错误配置保留 Last Known Good，env Provider 作为 break-glass，不与数据库 Provider 混写。
- 正式登录验证签名 ID Token 的 issuer/audience/azp/iat/exp/JWKS/subject，并绑定 state、S256 PKCE、RFC 9207 `iss` 与一次性 nonce。nonce 原值只出现在当次授权 URL，shared verification store 只保存 hash 与 provider binding：配置 secondary storage 时使用 Redis，否则使用数据库；没有进程内 Map、没有全局 verification 双写，也不依赖伪 CAS。
- `/sign-in/oauth2` 与 `/oauth2/link` 的 BetterAuth 调用顺序不同，分别由授权参数注入与 URL 返回前 shared-store 更新处理；missing/wrong/expired/replayed state/nonce、并发 flow、跨 auth instance callback 和更新失败均 fail closed。
- 可信姓名、头像、钉钉 title/user id 只从验证后的 ID Token + userinfo subject 绑定产生；请求不能伪造这些字段，Session/Public API 不投影钉钉字段，外部用户默认没有 EasyAuth 准入。
