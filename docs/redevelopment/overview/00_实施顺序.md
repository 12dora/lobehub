# 实施顺序与关键路径

> 本文件是整个交付包的执行入口。严格顺序以安全边界和运行时依赖为准，而不是以页面完成度为准。
> **G0 已于 2026-07-16 完成定稿**，决策记录见 `02_开工门禁与业务决策.md`（含 Authentik/EasyAuth 接入、重启激活按钮、私网放行等与默认建议不同的结论）。
> **阶段 0 环境准备已执行完毕**（同日），Authentik OIDC Client、EasyAuth 应用注册、Vault、dev 基础设施均已就绪，详见 `03_阶段0_环境准备记录.md`。

## 1. 总顺序

```text

  ↓

  ↓
W2 /admin 壳 + 用户/子管理员管理
  ↓

  ↓

  ↓

```

## 3. 不得调整的先后关系

1. **M02 必须早于任何管理员 Mutation。** 管理页面可以做静态原型，但不得接真实写接口。
2. **M05 必须早于用管理员默认值驱动生产运行时。** 否则客户端与服务端可能得到不同配置。
3. **M06 必须早于 M07–M10 的托管模式切换。** 仅隐藏用户 UI 不能阻止旧 API 被直接调用。
4. **M07–M09 必须早于 M10 发布依赖这些资源的 Agent。** Agent 发布时必须能校验 Provider、Model、Skill、Connector Revision。
5. **M11 必须独立灰度。** OIDC 配置错误可能导致全员无法登录，不能与 Branding 或大规模数据迁移捆绑上线。
6. **M12 最后切换默认平台名。** 先完成字符串扫描和登录/邮件/Manifest 回归，避免用户可见名称不一致。

## 4. 建议并行工作流

### 工作流 A：平台基础与服务端

M00 → M01 → M02 → M05 → M06 → M07/M08/M09 → M10。

### 工作流 B：管理端 UI

M03 壳层完成后，可并行实现 M04、M05、M07–M12 的页面；所有写操作先指向 Mock Contract，待服务端接口稳定后联调。

### 工作流 C：安全与运维

M13、M14 从 W1 开始参与设计评审，不等功能开发结束才介入。Secret、SSRF、审计、Revision、缓存键和指标命名必须在各模块建表/API 前定稿。

### 工作流 D：测试与上游同步

M15 从第一批 PR 起维护权限矩阵、E2E 基架、迁移回滚脚本和补丁台账；每两周对上游目标分支做一次 Rebase CI。

## 5. 推荐里程碑

- **Milestone A：安全后台骨架。** M00–M04 完成；普通用户无法进入 `/admin`；可安全维护子管理员。
- **Milestone B：策略可控。** M05–M06 完成；默认值继承与旧写接口封锁通过测试。
- **Milestone C：AI 资源托管。** M07–M09 完成；用户只能使用发布资源，不能配置全局定义。
- **Milestone D：统一助理。** M10 完成；默认 Inbox 可由平台接管且历史会话不受影响。
- **Milestone E：企业登录与品牌。** M11–M12 完成；Authentik 灰度成功，平台名全面一致。
- **Milestone F：生产就绪。** M13–M15 完成；完成灾备、回滚、Rebase 和性能演练。

## 6. 上线策略

每个能力按 `建表 → 只读 → 管理端写入 Draft → 测试/校验 → 发布但不生效 → 小范围生效 → 全量生效` 推进。任何模块不得从“未部署”直接切到“强制托管”。
