# Q06・生产就绪 Preflight / 回滚 / 灾备演练运行说明

本门禁交付 **可执行生产就绪证据契约与演练 harness**，不是生产已签字放行。

## 范围

| 路径                                                    | 职责                                                                                                  |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `scripts/enterprise/preflight.ts`                       | 薄入口：`validate-harness` / `preflight` / `production-authorized` / `dispatch` / `emit-default-plan` |
| `scripts/enterprise/recovery-drill.ts`                  | 备份恢复与应用版本回滚兼容演练入口                                                                    |
| `scripts/enterprise/production-readiness/**`            | 严格 Zod 契约、证据评估、命令白名单、恢复演练实现                                                     |
| `docs/enterprise/runbooks/**`                           | 运维可执行 Runbook                                                                                    |
| `.github/workflows/enterprise-production-readiness.yml` | CI harness/contract 校验（**非**生产 passed）                                                         |

## 本地命令

```bash
# 契约 / harness 校验（不得写出 production overall=passed）
bun run enterprise:preflight validate-harness \
  --candidate .records/enterprise-production-readiness/candidate.json \
  --plan .records/enterprise-production-readiness/plan.json \
  --evidence-dir .records/enterprise-production-readiness/evidence \
  --output .records/enterprise-production-readiness/report.json

# 生成默认 Milestone A–F 发布计划
bun run enterprise:preflight emit-default-plan \
  --candidate-sha "$(git rev-parse HEAD)" \
  --release-id "rc-local-demo" \
  --output .records/enterprise-production-readiness/plan.json

# 只读解析 allowlisted 命令（默认 dry-run）
bun run enterprise:preflight dispatch --command-id preflight-validate

# 本地 harness 备份恢复（owned 临时 PostgreSQL；scope=local-harness）
bun run enterprise:recovery-drill backup-restore \
  --candidate-sha "$(git rev-parse HEAD)" \
  --schema-tag "0136_m11_identity_secret_state_null_guard" \
  --scope local-harness \
  --output .records/enterprise-production-readiness/evidence/backup-restore.json

# 应用版本回滚兼容（无 baseline probe marker 时为 unverified，永不 passed）
bun run enterprise:recovery-drill app-rollback \
  --candidate-sha "$(git rev-parse HEAD)" \
  --scope local-harness \
  --output .records/enterprise-production-readiness/evidence/app-rollback.json
```

## 证据边界

允许：短/完整 commit SHA、计数、gate id/outcome、schema 版本、时间戳/新鲜度、命令 id、SHA-256 摘要、稳定分类。

禁止：连接串、主机名、URL、token、密文、Secret 引用原文、原始 DB 行、commit message、私有 payload。

## 结果语义

| overall / status              | 含义                                                                                                                   |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `passed`                      | 仅当 `production-authorized` 模式 + 仓库钉死 Ed25519 trust policy 校验通过，且七门禁均为 production 环境签名证据时可达 |
| `failed`                      | 签名/重放/摘要失败、门禁失败、新鲜度失败、候选不一致、清理失败等                                                       |
| `unverified` / `not-executed` | 缺证据、仅 harness、baseline materialize/probe 不可执行、生产公钥未配置；**不得**记作生产通过                          |

硬约束：

- 自声明 `scope: production-authorized`、`--production-ack`、任意 trust-policy 路径/环境变量 **不能** 升级生产通过。
- 仓库内 `PRODUCTION_TRUST_POLICY` 当前 **无生产公钥** 且 `productionPassEnabled=false`，CLI 生产 overall pass 在 reviewed 公钥合入前 **不可能**。测试密钥仅在 test fixtures。
- 应用回滚 **禁止** marker 文件授权；必须 materialize 钉死 baseline commit 并执行 baseline 包边界。
- 备份恢复 harness 永远是 `local-harness`/`ci-harness`；生产路径需要外部 backup + 签名 provenance，且不得 seed 生产源库。
- 证据年龄只看 `generatedAt`；`observedAt` 不能把过期证据刷成 fresh。
- `validate-harness` / CI 即使契约全绿，也 **不得** 发出 production `overall=passed`。

## Recovery → Preflight 证据流

1. `bun run enterprise:recovery-drill backup-restore ... --output evidence/backup-restore.json`
2. CLI 写出 `backup-restore.raw.json`（正式报告）与 `backup-restore.json`（含 `artifactSha256`/`generatedAt`/`gate` 的 preflight envelope）
3. `bun run enterprise:preflight validate-harness --evidence-dir evidence ...` 直接加载 envelope，无需手工改字段
4. `artifactSha256` 是 raw 报告的 SHA-256，加载后与 envelope 字段交叉校验
