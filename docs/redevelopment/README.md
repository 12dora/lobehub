## 1. 包内内容

本包不是把总设计机械切成多个章节，而是按**可独立开发、可独立评审、可独立验收、可由 Feature Flag 回退**的工程模块重新组织。每个模块包含：

- 目标、范围和明确非范围。
- 前置依赖与阻断条件。
- 现有源码落点和建议新增目录。
- 数据模型、tRPC API、服务端执行链和前端 UI。
- 分 PR 实施步骤、测试矩阵、上线与回滚。
- 验收标准、风险和移交物。

目录：


## 2. 关键架构决策

1. `/admin` 使用独立布局和独立路由树，不嵌入普通用户设置页。
2. 平台资源使用独立平台表，不创建“系统用户”承载全局 Provider、Model、Skill、Connector 或 Agent。
3. 服务端 RBAC 是唯一授权依据；前端隐藏菜单只用于体验优化，不构成安全控制。
4. 用户设置采用“内置默认值 → 平台默认值 → 用户显式覆盖 → 平台锁定值”的统一解析器。
5. AI、Skill、Connector 和 Agent 使用 Draft / Published / Archived 与不可变 Revision，不直接编辑线上快照。
6. 外部登录 OIDC 首版采用数据库配置、在线校验、发布后经管理后台内置“重启激活”按钮受控重启生效，不宣称热更新。
7. Branding 只替换用户可见信息；内部包名、协议 ID、数据库标识、许可证文本保持稳定。
8. 企业代码集中在新增目录和少数稳定挂载点，所有上游直接修改进入补丁台账。
9. 认证唯一企业 IdP 为 Authentik（上游对接钉钉，透传钉钉用户名）；平台授权经 EasyAuth（钉钉审批）授予后同步至内建 RBAC，运行时以内建 RBAC 为唯一执行点；用户使用 AIHub 需先经 EasyAuth 授予基础访问权限。

## 3. 开工前硬门禁（已于 2026-07-16 定稿）

全部门禁与业务规则已确认，完整决策记录见 `00_实施总览/02_开工门禁与业务决策.md`。要点：

- 用户可在管理员发布的模型范围内自由选择；Connector 默认每用户 OAuth；平台 Agent 分发规则按 mandatory/default/optional。
- 平台 Secret 主密钥采用 KMS/Vault。
- OIDC 发布后由管理后台内置“重启激活”按钮触发受控重启；保留本地 Break-glass 管理员。
- 部署形态为公网可达的单机私有部署（公网域名反代本机）；Connector 默认放行私网/本机地址，云 Metadata 地址仍阻断。
- 开发前仍需在测试环境验证数据库迁移、Redis、对象存储、邮件、KMS/Vault，以及 Authentik OIDC Client 与 EasyAuth 应用注册。
- **阶段 0 环境准备已于 2026-07-16 执行完毕**（Authentik/EasyAuth 注册、Vault、dev 基础设施、env 直配登录接通），结果与遗留事项见 `00_实施总览/03_阶段0_环境准备记录.md`。
