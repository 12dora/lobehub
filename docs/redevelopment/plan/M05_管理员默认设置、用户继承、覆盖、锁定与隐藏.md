# M05 · 管理员默认设置、用户继承、覆盖、锁定与隐藏

> 波次：W3  
> 估算：3–4 人周  
> 前置依赖：M01、M02、M03  
> 源码基线：LobeHub 2.2.10（设计基线提交 4bab1636408e60a7ee17b640490fbf33a310a325）

## 1. 交付目标

- 实现服务端统一的 Effective Configuration Resolver。
- 区分用户“未设置”和“显式设置”，保证平台默认变化时行为正确。
- 支持默认、锁定、隐藏和恢复默认，并保持旧设置兼容。

## 2. 范围

- 设置定义注册表、路径级策略、用户显式覆盖、管理端策略编辑、用户端来源提示。
- 改造 `getUserState` 和关键服务端运行时读取最终配置。
- 提供旧整对象 `updateSettings` 到新 Patch 语义的兼容 Adapter。

## 3. 明确非范围

- 不允许管理员写任意 JSON Path。
- 不把 Key Vault、API Key 等 Secret 作为平台默认设置。
- 不一次性重写所有用户 `user_settings`。

## 6. 目标设计

- 策略模型建议拆为 `mode=user|default|locked` 与 `visibility=visible|hidden`；管理 UI 可提供 Default/Locked/Hidden 预设。
- 解析顺序：内置默认 → 平台 default → 用户显式 override；若 mode=locked，最终值强制为平台值。
- `user_setting_overrides` 的“行存在”表示用户显式意图，即使值等于当前默认也不能丢弃。
- 锁定时保留原 Override 行但运行时忽略；解锁后恢复用户值，除非用户主动恢复默认。
- 所有可配置路径必须在 Registry 中有 Zod Schema、默认来源、敏感级别和适用端。

## 7. 数据模型与持久化

- `platform_setting_policies`：path、mode、visibility、value、schemaVersion、revision、status。
- `user_setting_overrides`：userId、path、value、updatedAt；唯一 `(user_id,path)`。
- `platform_resource_revisions` 保存已发布策略快照。

## 8. 服务端 API / Contract

- `admin.settings.getDraft`、`validateDraft`、`saveDraft`、`publish`、`rollback`。
- `user.getEffectiveSettings`：返回 values + 每路径 source/locked/hidden 元数据。
- `user.patchSettingOverride({path,value})`。
- `user.resetSettingOverride({path})`。
- 旧 `user.updateSettings`：展开为已注册路径 Patch，拒绝 locked/unknown。

## 9. 管理端与用户端 UI

- 管理页面按设置分组复用普通设置控件，增加模式、默认值、隐藏、变更预览。
- 用户端 locked 控件禁用并显示“由组织管理”；default 且已覆盖显示“使用我的设置/恢复组织默认”。
- hidden 路径不渲染；服务端仍决定最终值。
- 批量发布前显示受影响用户估算，不扫描全量用户同步写入。

## 10. 运行时接入

- 所有服务端调用模型、系统 Agent、工具策略的代码使用 Resolver；禁止只依赖客户端 Store。
- Resolver 以 Registry Version + Platform Revision + User Override Revision 为缓存键。
- 当 Flag 关闭时返回当前内置默认 + 旧 user_settings 语义。

## 12. 测试清单

- 未覆盖用户在平台默认改变后自动得到新值。
- 已覆盖用户保持原值；即使原值等于旧默认，也被视为显式覆盖。
- 锁定字段的 UI 和直接 API 写入都失败。
- 解锁后恢复用户原覆盖。
- unknown path、错误类型、跨端不适用路径被拒绝。

## 13. 上线与回滚

- 先 Shadow 计算新旧结果并记录差异，不改变响应。
- 差异率可接受后，对内部测试用户启用；随后全量。
- 关闭 Flag 时仍保留 Override 数据，不删除。

## 14. Definition of Done

- 客户端和服务端对同一用户、同一 Revision 得到相同 Effective Settings。
- 单路径恢复默认不删除其他设置。
- 设置发布支持 Revision 冲突和回滚。

## 15. 主要风险与控制

- Registry 漏接服务端读取点会产生不一致；建立静态扫描/代码审查清单。
- 把 hidden 等同 locked 会造成语义混乱；数据模型中分离可见性和控制模式。
