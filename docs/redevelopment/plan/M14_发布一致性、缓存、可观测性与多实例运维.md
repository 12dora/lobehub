# M14 · 发布一致性、缓存、可观测性与多实例运维

> 波次：W1–W8  
> 估算：贯穿，集中 2–3 人周  
> 前置依赖：M01  
> 源码基线：LobeHub 2.2.10（设计基线提交 4bab1636408e60a7ee17b640490fbf33a310a325）

## 1. 交付目标

- 确保配置发布在多实例环境中可预测、一致、可回滚。
- 提供 Revision、缓存失效、实例状态、Job 进度、指标和告警。
- 让管理员系统页能判断“已发布但未生效”的具体原因。

## 2. 范围

- 配置事件、Redis Version Key、实例 Revision 上报、缓存策略、Metrics、Structured Logs、健康检查和系统页。
- 覆盖 Settings、AI、Skill、Connector、Agent、OIDC、Branding。

## 3. 明确非范围

- 不以 Redis 为事实源。
- 不要求强一致跨实例分布式事务。
- 不把完整配置或 Secret 放入 Metrics/日志。

## 4. 当前源码落点

- `apps/server/src/runtimeConfig/` 与 `featureFlags/index.ts`：Redis/Env Snapshot。
- 已有 Observability/OTel 包、健康检查和 Job/Queue 模式。

## 5. 建议新增目录/文件

- `apps/server/src/enterprise/runtimeConfig/`。
- `apps/server/src/enterprise/observability/`。
- `src/enterprise/client/routes/admin/system/`。

## 6. 目标设计

- 每个领域有 monotonically increasing Revision 或不可变 ID；缓存键包含 Revision。
- 发布后写数据库，再发布失效事件；事件丢失时 TTL 和 Version Key 轮询最终收敛。
- 实例上报 loadedRevision、loadedAt、source、lastError；OIDC 单独上报 active startup revision。
- 读取失败可使用 LKG 的领域必须显式定义；权限和封禁默认 fail closed。
- Job 进度按处理量/失败量/游标展示，支持取消但不回滚已完成的幂等项。

## 7. 数据模型与持久化

- 使用 M01 `platform_jobs` 和 Revision 表；可新增 `platform_instance_heartbeats` 或通过 Redis/Telemetry 上报。

## 8. 服务端 API / Contract

- `admin.system.getStatus`、`getInstanceRevisions`、`getJobs`、`retryJob`、`cancelJob`。
- 只允许系统管理员查看，返回经过清洗的错误分类。

## 9. 管理端与用户端 UI

- 系统页显示数据库、Redis、对象存储、邮件、KMS、各领域 Revision、实例不一致、Pending Restart 和最近 Job。
- 不在页面展示原始环境变量或连接串。

## 10. 运行时接入

- 关键指标：发布成功/失败/冲突、缓存命中、Revision Lag、Guard 拒绝、SSRF 拒绝、OIDC 登录、Job backlog、Agent materialization。
- 结构化日志字段：requestId、actorId hash、action、target、revision、result、duration、errorClass。

## 11. 分 PR 实施步骤

1. PR-O01：配置事件和领域缓存基类。
2. PR-O02：实例 Revision/LKG 状态和健康检查。
3. PR-O03：Metrics/Logs/Alerts。
4. PR-O04：Admin System/Jobs 页面。
5. PR-O05：多实例故障和 Redis 丢失演练。

## 12. 测试清单

- 发布后各实例在 SLA 内收敛。
- Redis 重启后可从数据库重建。
- 失效事件丢失仍可通过 Version/TTL 收敛。
- 实例 Revision 不一致有告警和页面提示。

## 13. 上线与回滚

- 先在测试环境模拟 2–3 实例、Redis 重启、网络分区。
- 关键告警在正式启用托管资源前上线。

## 14. Definition of Done

- 所有发布型模块具备可观测 Revision。
- 故障时能判断数据库、缓存、实例还是外部服务问题。
- Runbook 覆盖 Redis、KMS、OIDC、Job 堵塞。

## 15. 主要风险与控制

- 指标高基数；禁止 userId、resourceId 无控制地作为 Metrics Label。
- LKG 使用不当会掩盖权限变更；按领域明确可否降级。

## 16. 模块移交物

- 缓存/事件框架、指标、日志、告警、系统页、故障演练与 Runbook。
