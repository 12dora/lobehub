# M15 · 测试、数据库迁移、灰度上线、回滚与上游持续同步

> 波次：W1–W8  
> 估算：贯穿，集中 3–4 人周  
> 前置依赖：M00  
> 源码基线：LobeHub 2.2.10（设计基线提交 4bab1636408e60a7ee17b640490fbf33a310a325）

## 1. 交付目标

- 建立从单元、权限矩阵、集成、E2E 到升级/回滚的完整质量门禁。
- 把上游兼容性作为持续工作，而不是项目结束时一次性 Rebase。
- 形成可执行的生产发布和灾难恢复流程。

## 2. 范围

- 测试基架、迁移波次、数据校验、灰度、Feature Flag、回滚、Rebase CI、补丁台账、版本发布。
- 覆盖 Web 和 Electron 关键路由。
- 建立 Definition of Done 和发布签字清单。

## 3. 明确非范围

- 不以手工冒烟替代权限/安全自动化测试。
- 不在同一发布窗口首次启用多个高风险模块。
- 不在应用回滚时立即删除新增数据库结构。

## 4. 当前源码落点

- 根脚本：`bun run check`、`type-check`、Vitest、Playwright、`db:migrate`。
- `packages/database/src/models/__tests__/drizzleMigration.test.ts`。
- `e2e/`、路由同步测试、现有 Snapshot。
- `packages/database/migrations/`。

## 5. 建议新增目录/文件

- `e2e/enterprise-admin/`。
- `tests/enterprise/permission-matrix/`。
- `scripts/enterprise/preflight.ts`、`verify-migration.ts`、`rebase-report.ts`。
- `docs/enterprise-patches/patch-ledger.md`。

## 6. 目标设计

- 每个 PR 必须声明 Flag、Migration、Rollback、权限和审计影响。
- 权限矩阵用数据驱动方式遍历角色×API，不逐个手写零散用例。
- 迁移采用 expand/contract：先增结构和双读/影子，再切换，最后在后续版本清理。
- 上游直接改动限制在补丁台账列出的稳定文件，新增代码尽量独立。
- 定期对上游目标分支运行 Rebase CI、类型检查、DB Migration 和关键 E2E。

## 7. 数据模型与持久化

- Migration 0：平台空表；1：RBAC/Audit；2：Settings；3：AI；4：Skill/Connector；5：Agent；6：OIDC/Branding。
- 所有 DROP/重命名延迟至少一个稳定版本并独立变更。

## 8. 服务端 API / Contract

- 测试专用 Caller/Factory，避免通过生产后门创建管理员。
- 发布工具只操作 Feature Flag/Revision，不直接改业务表。

## 9. 管理端与用户端 UI

- E2E 覆盖管理员进入、用户管理、设置继承、托管 API 拒绝、资源发布、Agent Inbox、OIDC 测试、Branding。
- 截图回归覆盖主题和核心 Branding 页面。

## 10. 运行时接入

- 运行时按 Flag 灰度；数据写入先 Draft，Published 切换可回滚。
- 每个生产波次设置停止条件、监控窗口、负责人和回滚命令。

## 11. 分 PR 实施步骤

1. PR-Q01：测试 Fixture、管理员/普通用户/工作区角色工厂。
2. PR-Q02：权限矩阵和 Managed Guard 绕过测试。
3. PR-Q03：Migration Snapshot、升级/回滚验证。
4. PR-Q04：企业 Admin E2E 和截图回归。
5. PR-Q05：上游 Rebase CI、补丁报告。
6. PR-Q06：生产 Preflight、Runbook、灾备演练。

## 12. 测试清单

- 从 2.2.10 生产数据脱敏快照升级成功。
- 应用版本回滚后旧功能仍可运行，新增表不阻塞。
- 上游 Rebase 后核心 E2E 通过。
- 备份恢复后 Revision、Audit、Secret 引用一致。

## 13. 上线与回滚

- 按 Milestone A–F 发布；OIDC、Connector 共享账号、默认 Inbox、Branding 名称切换分别独立窗口。
- 每次波次完成一次回滚演练，不只写回滚文档。

## 14. Definition of Done

- CI 门禁、迁移验证、E2E、性能和安全测试全部通过。
- 有补丁台账、升级报告、发布/回滚 Runbook。
- 运维能在无研发临场指导下执行常见恢复。

## 15. 主要风险与控制

- 上游快速变化导致测试脆弱；优先测试契约和关键行为，不依赖过多 DOM 细节。
- 长期不 Rebase 会使扩展层失去意义；固定同步节奏和负责人。

## 16. 模块移交物

- 测试套件、迁移脚本、Preflight、发布/回滚/灾备 Runbook、Rebase CI、补丁台账。
