# M04 · 用户、会话与子管理员管理

> 波次：W2  
> 估算：2–3 人周  
> 前置依赖：M01、M02、M03  
> 源码基线：LobeHub 2.2.10（设计基线提交 4bab1636408e60a7ee17b640490fbf33a310a325）

## 1. 交付目标

- 让授权管理员查询用户、封禁/解封、撤销会话和分配平台角色。
- 提供可审计、可确认、不可误伤最后超级管理员的操作链。
- 把子管理员管理纳入同一个平台 RBAC 模型。

## 2. 范围

- 用户列表、详情、状态、登录方式、最近活动、平台角色和危险操作。
- 封禁/解封、撤销全部会话、角色授予/移除/过期。
- 首版支持导出受限元数据，不导出消息内容。

## 3. 明确非范围

- 首版不做模拟登录。
- 首版不做物理删除用户和批量重写用户数据。
- 不允许管理员查看用户密码、OAuth Token、Provider Key 或消息正文。

## 4. 当前源码落点

- `packages/database/src/schemas/user.ts`：`role`、`banned`、`banReason`、`banExpires`、`lastActiveAt`。
- `packages/database/src/schemas/betterAuth.ts`：Session/Account。
- `src/libs/better-auth/define-config.ts`：`admin()` 插件。
- `apps/server/src/routers/lambda/user.ts` 与 `packages/database/src/models/user.ts`。

## 5. 建议新增目录/文件

- `apps/server/src/enterprise/routers/admin/users.ts`。
- `apps/server/src/enterprise/services/adminUserService.ts`。
- `src/enterprise/client/routes/admin/users/`。

## 6. 目标设计

- 列表使用游标分页，搜索字段规范化；禁止 `%` 无界模糊查询造成全表扫描。
- 封禁与角色变更要求 `reason`，高风险操作要求近期重新认证。
- 撤销 Session 使用 Better Auth 数据模型/服务，不直接删除未知关联记录。
- 角色分配调用 M02 的 `replaceGlobalUserRoles`；工作区角色保持不变。
- 自操作限制：管理员不能封禁自己；不能撤销自己当前 Session 以外的全部登录而无再次确认。

## 7. 数据模型与持久化

- 优先复用 users 和 Better Auth 表。
- 如需管理备注，新增 `platform_user_admin_notes`，与用户业务资料分离并审计。
- 不把角色列表写入 `users.role` JSON。

## 8. 服务端 API / Contract

- `admin.users.list`：query、status、role、createdRange、cursor。
- `admin.users.get`：用户基础资料、登录 Provider 摘要、角色、Session 数。
- `admin.users.ban` / `unban`。
- `admin.users.revokeSessions`。
- `admin.users.replaceGlobalRoles`。
- `admin.users.getAuditTrail`。

## 9. 管理端与用户端 UI

- 表格列：用户、邮箱、状态、角色、注册时间、最近活跃、登录方式。
- 详情页分 Overview、Access、Sessions、Audit；危险操作独立区域。
- 角色选择展示权限摘要、到期时间和影响提示。
- 封禁弹窗必须输入原因，永久封禁与定时封禁分开。

## 10. 运行时接入

- 封禁应在认证和关键业务 Procedure 双重检查，避免 Cookie Cache 短暂放行。
- 撤销 Session 后发布用户安全事件，使多实例缓存失效。

## 11. 分 PR 实施步骤

1. PR-018：User Admin Repository、游标分页、索引验证。
2. PR-019：列表/详情只读 API 与 UI。
3. PR-020：封禁/解封/Session 撤销与审计。
4. PR-021：平台角色分配、最后管理员保护联调。

## 12. 测试清单

- 普通管理员只能执行角色允许的动作。
- 封禁用户的现有 Session 在约定时限内失效。
- 撤销 Session 不影响其他用户。
- 角色变更不删除任何 workspace role。
- 最后一名超级管理员保护覆盖封禁、角色移除和到期。

## 13. 上线与回滚

- 先发布只读列表，再启用写操作。
- 批量操作首版关闭；需要批量时先做 Dry-run 和最大数量限制。

## 14. Definition of Done

- 列表在目标用户量下满足性能预算。
- 所有危险操作有 reason、二次确认和 Audit。
- 无敏感凭据展示或日志泄露。

## 15. 主要风险与控制

- Better Auth 内部 Schema 变化会影响 Session 操作；封装服务并跟踪上游版本。
- 用户搜索可能泄露信息；只有 `platform_user:read` 可用，日志不记录完整查询词。

## 16. 模块移交物

- 用户管理 API/UI、角色分配、会话撤销、审计和运维说明。
