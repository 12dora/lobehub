# 配置云端沙箱

云端沙箱用于内置的代码执行、Shell 命令、文件操作和文件导出工具。自托管部署默认使用本地 Docker 沙箱，因此不依赖 LobeHub Market。你仍然可以把同一套工具能力切换到 Market，或兼容 Onlyboxes 的沙箱提供方。

## 核心环境变量

### `SANDBOX_PROVIDER`

- 类型：可选
- 描述：选择服务端使用的沙箱提供方。
- 默认值：`local`
- 示例：`onlyboxes`

支持的取值：

- `local`：在宿主机 Docker 上运行隔离沙箱容器。需要 Docker 套接字（或 TCP 主机）以及 `aihub-sandbox` 镜像。
- `market`：使用现有 Market 沙箱（需要社区 / Market 个人档案）。
- `onlyboxes`：使用兼容 Onlyboxes 的自托管沙箱 Console。

### `MARKET_BASE_URL`

- 类型：可选
- 描述：Market 服务的基础 URL。使用官方 Market 时无需配置；仅当你需要连接自托管或专用 Market 服务时设置。
- 默认值：`https://market.lobehub.com`
- 示例：`https://market.example.com`

### `MARKET_TRUSTED_CLIENT_ID`

- 类型：可选
- 描述：Market Trusted Client 的客户端 ID，用于让 LobeHub 服务端代表当前用户调用 Market 能力。需要由对应 Market 服务登记。
- 默认值：-
- 示例：`lobechat-com`

### `MARKET_TRUSTED_CLIENT_SECRET`

- 类型：可选
- 描述：Market Trusted Client 的共享密钥，必须与对应 Market 服务端配置一致。
- 默认值：-
- 示例：`your-market-trusted-client-secret`

### `ONLYBOXES_BASE_URL`

- 类型：当 `SANDBOX_PROVIDER=onlyboxes` 时必填
- 描述：Onlyboxes Console API 的基础 URL，不需要包含 `/api/v1`。
- 默认值：-
- 示例：`https://onlyboxes.example.com`

### `ONLYBOXES_JIT_SIGNING_KEY`

- 类型：当 `SANDBOX_PROVIDER=onlyboxes` 时必填
- 描述：用于签发 Onlyboxes MCP JIT Bearer Token 的 HMAC 密钥，必须与 Onlyboxes Console 的 `CONSOLE_JIT_SIGNING_KEY` 一致。
- 默认值：-
- 示例：`onlyboxes-jit-signing-secret`

### `ONLYBOXES_JIT_ISSUER`

- 类型：可选
- 描述：Onlyboxes JIT Token claims 中使用的签发方。
- 默认值：`APP_URL`
- 示例：`https://lobehub.example.com`

### `ONLYBOXES_JIT_TTL_SEC`

- 类型：可选
- 描述：LobeHub 签发的每个 Onlyboxes JIT Token 的有效期。
- 默认值：`1800`
- 示例：`900`

### `ONLYBOXES_LEASE_TTL_SEC`

- 类型：可选
- 描述：云端沙箱提供方创建持久终端会话时使用的租约时长。
- 默认值：`900`
- 示例：`3600`

## 本地 Docker 沙箱

`SANDBOX_PROVIDER=local`（默认）会用 `SANDBOX_LOCAL_IMAGE` 在宿主机 Docker 上按会话启动容器。Agent 的文件、Shell、代码工具仍走同一套 `lobe-cloud-sandbox` 接口，只换后端。

### 安全模型

- 工作负载在独立容器内以 uid `1000`（`sandbox`）运行，而不是 LobeHub 的 Node 进程用户。
- 默认网络是 `bridge`。若沙箱不应有出站网络，设置 `SANDBOX_LOCAL_NETWORK=none`。
- 内存、PID、CPU、空闲 TTL、输出大小、并发容器数由环境变量限制（见下表）。
- LobeHub 进程必须能访问 Docker API。把 `/var/run/docker.sock` 挂进应用容器（见 `docker-compose/enhanced/docker-compose.yml`）。能访问该套接字的人就能控制宿主机 Docker —— 把这次挂载当成特权信任边界。
- 应用镜像以 uid `1001`（组 `nodejs`）运行。典型 Linux 宿主机上套接字是 `root:docker`、权限 `0660`，只挂载不够：还要用 `group_add` / `DOCKER_GID` 补上宿主机 Docker GID。用 `stat -c '%g' /var/run/docker.sock`（Linux）或 `stat -f '%g' /var/run/docker.sock`（macOS）读取。套接字返回 `EACCES` 表示 GID 不对，并不是 Docker 没起来。
- 关闭平台 `sandbox` 模块（管理后台或 `LOBE_MODULES_DISABLED=sandbox`）会返回 `PLATFORM_MODULE_DISABLED`，不会导入 Docker 客户端，也不会对守护进程做健康探测。

### 镜像

单独构建并打标签（不要打进主应用镜像）：

```bash
bun run build:sandbox-image
# 打上 aihub-sandbox:<package version> 和 aihub-sandbox:latest
bun run build:sandbox-image -- --smoke   # 再在镜像里跑 tsx hello 和 unzip -v
```

镜像基于 `python:3.12-slim`，另外包含 Node 22、git、curl、unzip、固定版本的全局 `tsx`、编译工具链，以及常用的数据 / 文档 Python 库。默认工作目录是 `/mnt/data`。

### 限额与 Docker 连接

| 变量                               | 默认值                    | 说明                                         |
| -------------------------------- | ---------------------- | ------------------------------------------ |
| `SANDBOX_DOCKER_SOCKET`          | `/var/run/docker.sock` | Docker 守护进程的 Unix 套接字。                     |
| `SANDBOX_DOCKER_HOST`            | 未设置                    | 可选的 Docker TCP 地址（`tcp://127.0.0.1:2375`）。 |
| `SANDBOX_LOCAL_IMAGE`            | `aihub-sandbox:latest` | 沙箱容器使用的镜像。                                 |
| `SANDBOX_LOCAL_PULL_POLICY`      | `if-missing`           | `if-missing`、`always` 或 `never`。           |
| `SANDBOX_LOCAL_NETWORK`          | `bridge`               | `bridge` 或 `none`。                         |
| `SANDBOX_LOCAL_MEMORY_MB`        | `1024`                 | 每个沙箱容器的内存上限。                               |
| `SANDBOX_LOCAL_PIDS_LIMIT`       | `256`                  | 每个沙箱容器的 PID 上限。                            |
| `SANDBOX_LOCAL_CPUS`             | `1`                    | 每个沙箱容器的 CPU 配额。                            |
| `SANDBOX_LOCAL_TIMEOUT_MS`       | `120000`               | 工具执行超时。                                    |
| `SANDBOX_LOCAL_MAX_OUTPUT_BYTES` | `1048576`              | 捕获的 stdout/stderr 上限。                      |
| `SANDBOX_LOCAL_IDLE_TTL_SEC`     | `1800`                 | 空闲容器回收 TTL。                                |
| `SANDBOX_LOCAL_MAX_CONTAINERS`   | `8`                    | 同时存在的沙箱容器上限。                               |

最小配置：

```bash
SANDBOX_PROVIDER=local
SANDBOX_LOCAL_IMAGE=aihub-sandbox:latest
```

### 模块开关

企业平台模块 `sandbox` 控制该能力。关闭后，`execInSandbox` / `createSandboxService` 会以 `PLATFORM_MODULE_DISABLED` 失败，并且不会导入 Docker 客户端。

## Market 配置

若要改用 Market 而不是本地 Docker，设置 `SANDBOX_PROVIDER=market`。连接自托管或专用 Market 服务时，再设置 `MARKET_BASE_URL`：

```bash
SANDBOX_PROVIDER=market
MARKET_BASE_URL=https://market.example.com
```

如果该 Market 服务要求 LobeHub 服务端代表当前用户调用沙箱、凭据或技能能力，还需要配置 Trusted Client：

```bash
MARKET_TRUSTED_CLIENT_ID=lobechat-com
MARKET_TRUSTED_CLIENT_SECRET=your-market-trusted-client-secret
```

`MARKET_TRUSTED_CLIENT_ID` 需要在 Market 服务端的可信客户端白名单中，`MARKET_TRUSTED_CLIENT_SECRET` 需要与 Market 服务端共享密钥一致。未配置 Trusted Client 时，Market 侧需要认证的能力会继续使用现有的用户授权流程。

## Onlyboxes 运行时要求

配置的 Onlyboxes worker 需要暴露 `terminalExec` 和 `terminalResource`。LobeHub 使用 `terminalExec` 作为 Shell 命令、代码执行和文件操作的兼容层，并使用 `terminalResource` 通过预签名上传 URL 导出文件。

为了和 Market 沙箱保持能力对等，终端运行镜像应包含：

- `python3`，用于文件操作封装和 Python 执行
- `node`，用于 JavaScript 执行
- `npx` 以及可用的 `tsx`，用于 TypeScript 执行
- `base64`、`find`、`grep` 等常见 Shell 工具

使用 Onlyboxes 时的最小配置：

```bash
SANDBOX_PROVIDER=onlyboxes
ONLYBOXES_BASE_URL=https://onlyboxes.example.com
ONLYBOXES_JIT_SIGNING_KEY=onlyboxes-jit-signing-secret
```

Onlyboxes Console 侧需要配置同一个密钥：

```bash
CONSOLE_JIT_SIGNING_KEY=onlyboxes-jit-signing-secret
```

<Callout type={'info'}>
  文件导出仍会把沙箱内产物写入 LobeHub 配置的 S3 存储。如果用户需要下载沙箱生成的文件，请同时配置 S3
  相关环境变量。
</Callout>
