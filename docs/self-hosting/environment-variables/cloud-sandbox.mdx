# Configuring Cloud Sandbox

Cloud Sandbox powers the built-in code execution, shell command, file operation, and file export tools. Self-hosted deployments default to a local Docker sandbox so they do not depend on LobeHub Market. You can still switch the same tool surface to Market or an Onlyboxes-compatible sandbox provider.

## Core Environment Variables

### `SANDBOX_PROVIDER`

- Type: Optional
- Description: Selects the server-side sandbox provider.
- Default: `local`
- Example: `onlyboxes`

Supported values:

- `local`: Run isolated sandbox containers on the host Docker daemon. Requires a Docker socket (or TCP host) and the `aihub-sandbox` image.
- `market`: Use the existing Market sandbox (requires a community / Market profile).
- `onlyboxes`: Use an Onlyboxes-compatible self-hosted sandbox console.

### `MARKET_BASE_URL`

- Type: Optional
- Description: Base URL of the Market service. Leave it unset when using the official Market; set it only when connecting to a self-hosted or dedicated Market service.
- Default: `https://market.lobehub.com`
- Example: `https://market.example.com`

### `MARKET_TRUSTED_CLIENT_ID`

- Type: Optional
- Description: Market Trusted Client ID used by the LobeHub server to call Market capabilities on behalf of the current user. It must be registered by the target Market service.
- Default: -
- Example: `lobechat-com`

### `MARKET_TRUSTED_CLIENT_SECRET`

- Type: Optional
- Description: Shared secret for the Market Trusted Client. It must match the target Market service configuration.
- Default: -
- Example: `your-market-trusted-client-secret`

### `ONLYBOXES_BASE_URL`

- Type: Required when `SANDBOX_PROVIDER=onlyboxes`
- Description: Base URL of the Onlyboxes console API. Do not include `/api/v1`.
- Default: -
- Example: `https://onlyboxes.example.com`

### `ONLYBOXES_JIT_SIGNING_KEY`

- Type: Required when `SANDBOX_PROVIDER=onlyboxes`
- Description: HMAC signing key used to mint Onlyboxes MCP JIT bearer tokens. It must match the Onlyboxes console `CONSOLE_JIT_SIGNING_KEY`.
- Default: -
- Example: `onlyboxes-jit-signing-secret`

### `ONLYBOXES_JIT_ISSUER`

- Type: Optional
- Description: Issuer used in Onlyboxes JIT token claims.
- Default: `APP_URL`
- Example: `https://lobehub.example.com`

### `ONLYBOXES_JIT_TTL_SEC`

- Type: Optional
- Description: Lifetime of each Onlyboxes JIT token minted by LobeHub.
- Default: `1800`
- Example: `900`

### `ONLYBOXES_LEASE_TTL_SEC`

- Type: Optional
- Description: Lease duration for persistent terminal sessions created by the Cloud Sandbox provider.
- Default: `900`
- Example: `3600`

## Local Docker sandbox

`SANDBOX_PROVIDER=local` (the default) starts per-session containers from `SANDBOX_LOCAL_IMAGE` using the host Docker engine. Agent file, shell, and code tools keep the same `lobe-cloud-sandbox` surface; only the backend changes.

### Security model

- Workloads run as uid `1000` (`sandbox`) inside a dedicated container, not as the LobeHub Node process.
- The default network is `bridge`. Set `SANDBOX_LOCAL_NETWORK=none` if the sandbox should have no outbound network.
- Memory, PID, CPU, idle TTL, output size, and concurrent container caps are enforced from env (see variables below).
- The LobeHub process must be able to talk to the Docker API. Mount `/var/run/docker.sock` into the app container (see `docker-compose/enhanced/docker-compose.yml`). Anyone who can reach that socket can control the host Docker daemon — treat the mount as a privileged trust boundary.
- The app image runs as uid `1001` (group `nodejs`). On a typical Linux host the socket is `root:docker` mode `0660`, so a mount alone is not enough: add the host Docker GID with `group_add` / `DOCKER_GID`. Derive it with `stat -c '%g' /var/run/docker.sock` (Linux) or `stat -f '%g' /var/run/docker.sock` (macOS). `EACCES` on the socket means the GID is wrong, not that Docker is down.
- Turning off the platform `sandbox` module (admin console or `LOBE_MODULES_DISABLED=sandbox`) returns `PLATFORM_MODULE_DISABLED` and never opens a Docker client or health-probes the daemon.

### Image

Build and tag the sandbox image (not the main app image):

```bash
bun run build:sandbox-image
# tags aihub-sandbox:<package version> and aihub-sandbox:latest
bun run build:sandbox-image -- --smoke   # also runs tsx hello + unzip -v in the image
```

The image is `python:3.12-slim` plus Node 22, git, curl, unzip, a pinned global `tsx`, a compiler toolchain, and common data/document Python libraries. Default working directory is `/mnt/data`.

### Limits and Docker connection

| Variable                         | Default                | Description                                        |
| -------------------------------- | ---------------------- | -------------------------------------------------- |
| `SANDBOX_DOCKER_SOCKET`          | `/var/run/docker.sock` | Unix socket of the Docker daemon.                  |
| `SANDBOX_DOCKER_HOST`            | unset                  | Optional Docker TCP host (`tcp://127.0.0.1:2375`). |
| `SANDBOX_LOCAL_IMAGE`            | `aihub-sandbox:latest` | Image used for sandbox containers.                 |
| `SANDBOX_LOCAL_PULL_POLICY`      | `if-missing`           | `if-missing`, `always`, or `never`.                |
| `SANDBOX_LOCAL_NETWORK`          | `bridge`               | `bridge` or `none`.                                |
| `SANDBOX_LOCAL_MEMORY_MB`        | `1024`                 | Memory cap per sandbox container.                  |
| `SANDBOX_LOCAL_PIDS_LIMIT`       | `256`                  | PID cap per sandbox container.                     |
| `SANDBOX_LOCAL_CPUS`             | `1`                    | CPU quota per sandbox container.                   |
| `SANDBOX_LOCAL_TIMEOUT_MS`       | `120000`               | Tool execution timeout.                            |
| `SANDBOX_LOCAL_MAX_OUTPUT_BYTES` | `1048576`              | Captured stdout/stderr cap.                        |
| `SANDBOX_LOCAL_IDLE_TTL_SEC`     | `1800`                 | Idle container reclaim TTL.                        |
| `SANDBOX_LOCAL_MAX_CONTAINERS`   | `8`                    | Max concurrent sandbox containers.                 |

Minimum configuration:

```bash
SANDBOX_PROVIDER=local
SANDBOX_LOCAL_IMAGE=aihub-sandbox:latest
```

### Module switch

The enterprise platform module `sandbox` gates this capability. When it is off, `execInSandbox` / `createSandboxService` fail with `PLATFORM_MODULE_DISABLED` and the Docker client is not imported.

## Market Configuration

To use Market instead of local Docker, set `SANDBOX_PROVIDER=market`. To connect to a self-hosted or dedicated Market service, also set `MARKET_BASE_URL`:

```bash
SANDBOX_PROVIDER=market
MARKET_BASE_URL=https://market.example.com
```

If that Market service requires the LobeHub server to call sandbox, credential, or skill capabilities on behalf of the current user, also configure Trusted Client credentials:

```bash
MARKET_TRUSTED_CLIENT_ID=lobechat-com
MARKET_TRUSTED_CLIENT_SECRET=your-market-trusted-client-secret
```

`MARKET_TRUSTED_CLIENT_ID` must be registered in the Market service's trusted client allowlist, and `MARKET_TRUSTED_CLIENT_SECRET` must match the shared secret configured on the Market service. Without Trusted Client credentials, Market capabilities that require authentication continue to use the existing user authorization flow.

## Onlyboxes Runtime Requirements

The configured Onlyboxes worker should expose `terminalExec` and `terminalResource`. LobeHub uses `terminalExec` as the compatibility layer for shell commands, code execution, and file operations, and uses `terminalResource` for file export through a pre-signed upload URL.

For feature parity with the Market sandbox, the terminal runtime image should include:

- `python3`, used by file operation wrappers and Python execution
- `node`, used by JavaScript execution
- `npx` with access to `tsx`, used by TypeScript execution
- Standard shell utilities such as `base64`, `find`, and `grep`

Minimum configuration for using Onlyboxes:

```bash
SANDBOX_PROVIDER=onlyboxes
ONLYBOXES_BASE_URL=https://onlyboxes.example.com
ONLYBOXES_JIT_SIGNING_KEY=onlyboxes-jit-signing-secret
```

Set the same secret on the Onlyboxes console:

```bash
CONSOLE_JIT_SIGNING_KEY=onlyboxes-jit-signing-secret
```

<Callout type={'info'}>
  File export still writes the exported artifact to the configured LobeHub S3 storage. Configure the
  S3 environment variables when users need to download files generated inside the sandbox.
</Callout>
