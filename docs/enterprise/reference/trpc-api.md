# 企业 tRPC 接口清单

AIHub 二开的企业 tRPC 接口全部挂在 lambda 根路由下，分三个入口：管理端 `admin.*`（`apps/server/src/enterprise/routers/admin.ts` 的 mount 对象为唯一权威）、平台读侧 `platform.*`（`platform.ts`）、用户侧 `user.connectors.*`（`user/connectors.ts`，挂在 `user` 路由）。权限常量见 `packages/const/src/platform/permissions.ts` 的 `PLATFORM_PERMISSIONS`。

## admin.\* 子路由

所有 admin 过程共享 `adminBase`：`authedProcedure → serverDatabase → withActiveUser() → withAdminMutationRateLimit()`，再由 `withPlatformPermission(...)` 单闸鉴权。下表「权限」列为 `PLATFORM_PERMISSIONS.*` 常量名（省略前缀）。

## 管理端非 tRPC 接口（webapi）

multipart 文件上传不走 tRPC，另开 Next.js webapi 路由，但共用同一套鉴权事实：

| 接口                                                                    | 权限                   | 关键约束                                                                                                                                                                                                                                                                                                |
| ----------------------------------------------------------------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /webapi/admin/network-proxy/artifact?kind=engine\|geoip\|geosite` | NETWORK\_PROXY\_MANAGE | `checkAuth`（Better Auth 会话 cookie 或 `Oidc-Auth` 头）+ `withAdminWebapiGuard`（active-user → 单闸权限 → 危险 reauth → admin-mutation 限流 → 成功 / 失败都写审计）；必须带 `Content-Length`（缺失或 chunked=411，超 64 MiB=413），预检通过后才读 `formData()`；产物落地本实例，sha256 / size 流式校验 |

每个 `src/app/(backend)/webapi/admin/**` 下的 route 都必须在 `apps/server/src/enterprise/security/policy/adminWebapiRouteRegistry.ts` 登记（路径 → 权限 / 危险级 / reauth / 限流），同目录测试扫描目录逐一对账。

管理端授权注册表计数随本期从 `197/95/102` 增至 `214/101/113`（网络代理 +6 query / +11 mutation）；其它批次并行还会再加，**实际计数以 `adminProcedureAuthorizationRegistry.test.ts` 为准**。

## 接口统一规则

- **单闸鉴权**：每个 admin 过程只用一个 `withPlatformPermission`；需要多权限时用 `withAllPlatformPermissions([...])` 仍算单闸，保证「过程：权限门」1:1 便于授权对账。
- **变更类需 reason + expectedRevision**：所有写 / 发布 / 回滚过程带 `reason`；配置类过程带 `expectedRevision`（乐观并发 CAS，冲突则拒绝）。
- **草稿→发布生命周期**：aiProviders /aiModels/skills/connectors/agents/identityProviders 走「草稿 (saveDraft/updateDraft) → publish/applyImmediate → rollback」，读侧只暴露已发布版本；branding 已取消草稿（save 即发布）。
- **密钥字段 keep|replace|clear**：凭据 / 服务商 / 连接器 / 身份提供方的机密字段以三态语义更新（保持原值 / 写新值 / 清空），机密永不回读明文。
- **危险操作 reauth**：用户 ban/delete/ 角色变更、助理 archive/delete、身份提供方发布 / 停用、密钥轮换、系统重启、网络代理改出站去向（出口 / 订阅 / 装引擎）等需近期 reauth；`authMethod=oidc` 走 prompt=login 弹窗。
- **失败也写审计**：鉴权 / 校验失败（如 reauth-denied、写入失败）同样落审计事件，不因异常跳过审计。
- **列表分页**：列表过程统一 cursor + limit 游标分页（返回 `nextCursor`）。
- **Feature flag**：admin 面由 `ENABLE_PLATFORM_ADMIN` 控制；platform 用户侧由各 `ENABLE_PLATFORM_MANAGED_*` 独立启用，flag 关闭时读侧退化为空 / 默认。
