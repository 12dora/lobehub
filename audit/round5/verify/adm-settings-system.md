## Details

### adm-settings-system-D5-001 — DOWNGRADED

- **What the original claimed:** Same-path `?tab=` switches bypass the editors’ unsaved-change guards, unmounting the active editor and silently discarding its draft.

- **What I actually found:** Managed Resources blocks only when `pathname` changes ([ManagedResourcesPolicyPage.tsx:119](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/ManagedResourcesPolicyPage.tsx:119)). Settings Policy uses the same predicate ([useSettingsPolicyEditor.ts:101](/Users/konata/code/AIHub/src/enterprise/client/features/admin/settings/hooks/useSettingsPolicyEditor.ts:101)). The visible Unified Management surface updates only the search parameter through `setSearchParams(..., { replace: true })`, then conditionally renders exactly one editor ([UnifiedManagementPage.tsx:60](/Users/konata/code/AIHub/src/enterprise/client/features/admin/unified/UnifiedManagementPage.tsx:60)). React Router implements `setSearchParams` as navigation to `"?" + newSearchParams`, preserving the pathname ([lib.js:753](/Users/konata/code/AIHub/node_modules/react-router/dist/development/lib/dom/lib.js:753)); its blocker proceeds whenever the supplied predicate returns false ([router.js:1198](/Users/konata/code/AIHub/node_modules/react-router/dist/development/lib/router/router.js:1198)).

- **Refutation attempts:**
  - Checked the shared guard. `beforeunload` protects document unloads only; the in-app modal appears only after `useBlocker` reports `blocked` ([useUnsavedChangesGuard.ts:72](/Users/konata/code/AIHub/src/enterprise/client/features/admin/primitives/useUnsavedChangesGuard.ts:72), [useUnsavedChangesGuard.ts:78](/Users/konata/code/AIHub/src/enterprise/client/features/admin/primitives/useUnsavedChangesGuard.ts:78), [useUnsavedChangesGuard.ts:88](/Users/konata/code/AIHub/src/enterprise/client/features/admin/primitives/useUnsavedChangesGuard.ts:88)). It supplies no secondary same-path protection.
  - Checked the parent for a separate confirmation gate or retained mounting. It has neither; changing `tab` replaces one component type with the other ([UnifiedManagementPage.tsx:63](/Users/konata/code/AIHub/src/enterprise/client/features/admin/unified/UnifiedManagementPage.tsx:63), [UnifiedManagementPage.tsx:69](/Users/konata/code/AIHub/src/enterprise/client/features/admin/unified/UnifiedManagementPage.tsx:69)).
  - Checked for Managed Resources recovery storage or a parent/store-owned draft. Its policy draft, dirty flag, token, and revision are component state/ref values ([ManagedResourcesPolicyPage.tsx:98](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/ManagedResourcesPolicyPage.tsx:98)); repository-wide search found no managed-resource local/session-storage persistence. Remounting hydrates the server snapshot ([ManagedResourcesPolicyPage.tsx:139](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/ManagedResourcesPolicyPage.tsx:139)).
  - Checked Settings Policy recovery. Dirty drafts are written to `localStorage` ([useSettingsPolicyEditor.ts:183](/Users/konata/code/AIHub/src/enterprise/client/features/admin/settings/hooks/useSettingsPolicyEditor.ts:183), [localDraftStorage.ts:66](/Users/konata/code/AIHub/src/enterprise/client/features/admin/settings/localDraftStorage.ts:66)) and loaded on remount ([useSettingsPolicyEditor.ts:149](/Users/konata/code/AIHub/src/enterprise/client/features/admin/settings/hooks/useSettingsPolicyEditor.ts:149)). Thus its prompt contract is broken, but ordinary tab switching does not necessarily lose its draft.
  - Checked the established embedded-tab implementation. General Settings explicitly compares `search` when `embedded` ([GeneralSettingsPage.tsx:209](/Users/konata/code/AIHub/src/enterprise/client/features/admin/generalSettings/GeneralSettingsPage.tsx:209)), with a matching same-path test ([GeneralSettingsPage.test.tsx:178](/Users/konata/code/AIHub/src/enterprise/client/features/admin/generalSettings/GeneralSettingsPage.test.tsx:178)).
  - Checked relevant tests. Settings Policy tests only a cross-path transition ([SettingsPolicyPage.test.tsx:845](/Users/konata/code/AIHub/src/enterprise/client/features/admin/settings/SettingsPolicyPage.test.tsx:845)); the managed-resource navigation test exercises only the modal decision helper ([unsavedNavigationDecision.test.ts:5](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/unsavedNavigationDecision.test.ts:5)). There is no Unified Management integration test.
  - Checked reachability and scope. `/admin/unified` is the visible navigation surface, while standalone routes are hidden compatibility routes ([adminNavMeta.ts:109](/Users/konata/code/AIHub/src/enterprise/client/nav/adminNavMeta.ts:109)). The bug requires access to both tabs.
  - Checked the supplied baseline. All principal files involved are absent at `4bab1636408e60a7ee17b640490fbf33a310a325`; this is fork-owned, not an identical upstream defect.

- **Verdict rationale:** The functional defect is independently reproduced from the actual navigation and blocker implementations. The HIGH rating overstates the damage: Managed Resources contains five fixed policy-mode selections, not a large free-form policy document, and no persisted server state is deleted or corrupted. Settings Policy normally restores its durable local draft.

- **Corrected severity and scope:** **MEDIUM.** Silent loss affects unsaved Managed Resources mode changes when an administrator with both tab permissions switches tabs on `/admin/unified`. Settings Policy lacks the warning but generally retains its edits through local recovery.

### adm-settings-system-D5-002 — DOWNGRADED

- **What the original claimed:** “Keep my values” clears conflict state without obtaining a fresh CAS identity, so subsequent operations repeat the conflict indefinitely.

- **What I actually found:** Initial save or publish CAS errors enter a single boolean conflict state ([ManagedResourcesPolicyPage.tsx:201](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/ManagedResourcesPolicyPage.tsx:201), [ManagedResourcesPolicyPage.tsx:275](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/ManagedResourcesPolicyPage.tsx:275)). The banner always exposes “Keep my values,” including before any refresh/rebase ([ManagedResourcesPolicyPage.tsx:581](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/ManagedResourcesPolicyPage.tsx:581)). Its handler clears the conflict and marks the draft dirty without changing `activeDraftToken`, `baseRevision`, or the merge base ([ManagedResourcesPolicyPage.tsx:232](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/ManagedResourcesPolicyPage.tsx:232)). The resulting primary action is Save, which resubmits the unchanged stale token ([controller.ts:133](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/controller.ts:133), [ManagedResourcesPolicyPage.tsx:295](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/ManagedResourcesPolicyPage.tsx:295)).

- **Refutation attempts:**
  - Checked whether mutation failure automatically refreshes SWR or updates the token from an error payload. The catch only maps the error into local conflict state ([ManagedResourcesPolicyPage.tsx:348](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/ManagedResourcesPolicyPage.tsx:348)); the SWR hook disables focus revalidation and has no mutation-error refresh behavior ([useAdminManagedResources.ts:8](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/hooks/useAdminManagedResources.ts:8)).
  - Checked the service wrapper for token replacement. It forwards the supplied input directly ([actions.ts:14](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/actions.ts:14)); the client service likewise directly invokes the TRPC mutation ([adminManagedResources.ts:22](/Users/konata/code/AIHub/src/enterprise/client/services/adminManagedResources.ts:22)).
  - Checked the server transaction and CAS guard. Save locks the aggregate and rejects unless the supplied token exactly matches the current draft/revision checksum ([managedResourcePolicy.ts:88](/Users/konata/code/AIHub/apps/server/src/enterprise/services/managedResourcePolicy.ts:88)). Publish independently validates both revision and token under its lock ([managedResourcePolicy.ts:135](/Users/konata/code/AIHub/apps/server/src/enterprise/services/managedResourcePolicy.ts:135)). Tests explicitly establish that reusing a stale token is rejected ([managedResourcePolicy.test.ts:95](/Users/konata/code/AIHub/apps/server/src/enterprise/services/managedResourcePolicy.test.ts:95)) and concurrent saves allow only one writer ([managedResourcePolicy.test.ts:263](/Users/konata/code/AIHub/apps/server/src/enterprise/services/managedResourcePolicy.test.ts:263)).
  - Checked whether the report overstated the publish path. It did: after “Keep my values,” `dirty` is true, so direct publish is gated out ([ManagedResourcesPolicyPage.tsx:354](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/ManagedResourcesPolicyPage.tsx:354)). The reproducible loop is stale-token **save**, not an immediate publish retry.
  - Checked alternate recovery. “Refresh and rebase” fetches the latest snapshot and adopts its current token, revision, published state, and merge base before unlocking ([ManagedResourcesPolicyPage.tsx:242](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/ManagedResourcesPolicyPage.tsx:242)). After field-level conflicts, “Keep my values” is valid because that rebase has already refreshed the CAS identity.
  - Checked for server corruption or lost persisted data. The transaction and locked CAS reject stale writes before `replaceDraft`; local values remain in component memory while the conflict banner reappears.
  - Checked component tests. Controller tests cover rebase and primary-action selection ([controller.test.ts:142](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/controller.test.ts:142), [controller.test.ts:184](/Users/konata/code/AIHub/src/enterprise/client/features/admin/managedResources/controller.test.ts:184)), but no test renders the initial-conflict “Keep my values” path.
  - Checked the supplied baseline. The affected UI and managed-resource service files are absent at the baseline commit, so this is not an out-of-scope upstream defect.

- **Verdict rationale:** The initial-conflict action is genuinely broken: it cannot advance the CAS identity and predictably returns to conflict on Save. HIGH is nevertheless inflated because the server prevents stale overwrite, the local draft remains visible, and the adjacent rebase action successfully preserves it.

- **Corrected severity and scope:** **MEDIUM.** One conflict-recovery choice is misleading and non-progressing for concurrent-admin save/publish conflicts. It causes repeated failed requests and poor recovery UX, but not persisted-state corruption or unavoidable draft loss.
