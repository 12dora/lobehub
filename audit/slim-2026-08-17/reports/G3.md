## Helper design

`apps/server/src/enterprise/routers/moduleRouter.ts`

**Choice: tRPC v11.18 `lazy()` + post-import procedure wrap.**

- `lazy()` is exported from `@trpc/server/unstable-core-do-not-import` (not the public `@trpc/server` barrel). Verified in `node_modules/@trpc/server@11.18.0` (`dist/unstable-core-do-not-import.d.mts`).
- Loader is memoized by tRPC’s `once()`. `moduleRouter(...)` does **not** call `load()` at evaluation time.
- `DecorateCreateRouterOptions` unwraps `Lazy<T>` to `T`’s procedure record, so `LambdaRouter` / client types stay aligned. Call sites keep a type-only static import out of the graph by using `() => import('./x').then((m) => m.xRouter)`.
- Built procedures have no public `.use()` in v11. The wrap is a call-site function that preserves `_def` (input / type / existing middleware metadata) and is rebuilt with `createRouterFactory(source._def._config)` so lambda vs async root configs stay intact. Shape is `.use()`-compatible (function + `_def`).
- The **hot** check `isModuleEnabled(moduleId)` runs on every call (not just first load). Disabled modules still pay the import on first hit (needed to keep real procedure paths) and then throw `PLATFORM_MODULE_DISABLED` / `FORBIDDEN` with `details.moduleId`.
- `admin` / `platform` are not wrapped here (fork, guarded elsewhere).

Unit tests (`moduleRouter.test.ts`): enabled ⇒ delegates; disabled ⇒ FORBIDDEN + `moduleId`; import once; no import at evaluation time; flag re-checked after memoization.
