## What landed

Enterprise workers no longer start as tRPC import side-effects. They start from a registry at `instrumentation.register()` after `initBootModules()`, and a disabled module never loads that worker's graph (dynamic `import()` inside each spec).

High-frequency pollers now tell the scheduler whether a tick did work. After 3 dry ticks the delay doubles up to 60s, then snaps back to the base interval on the first real batch.

GatewayService, `/api/agent/*` bot/messenger/webhook paths, `/api/workflows`, and the moderation / network-proxy wrappers are gated the same way.

Idle backoff: after **3** consecutive `{ didWork: false }` ticks, delay ×2 each subsequent dry tick, capped at `maxIdleIntervalMs` (default 60_000). Any `{ didWork: true }` or `void` resets to `baseIntervalMs`. Failure backoff is unchanged. `.unref()` is still called on every timer.

`isPersistentEnterpriseWorkerRuntime()` is unchanged: production Node, not edge, not Vercel, not Lambda, `DATABASE_URL` set. Each `ensure*` still applies it.

## Flag mismatches

- `platformInstanceRegistryCleanup` belongs to `databaseIdp` (`modules.ts`). The registry skips it when that module is off. The worker still checks `ENABLE_DATABASE_OIDC` internally; G1's env-layer already maps that flag onto the module.
- Jobs that previously had **no** module flag now get one via the registry: `secretRewrap` (Vault predicate, core), `brandingAssetCleanup` (`branding`), `sharedOAuthKeepalive` / `connectorRuntimeAudit` (`managedConnectors`).

## Boot path (`src/instrumentation.ts`)

1. First `nodejs` step: `initBootModules()` (try/catch, non-blocking).
2. Existing admin / identity / heartbeat bootstraps (byte-identical).
3. `startEnterpriseWorkers()`.
4. GatewayService condition adds `isBootModuleEnabled('bots')` (import inside the `if`).

`POST /api/agent/gateway/start` returns HTTP 200 `{ ok:false, disabled:true }` when `bots` is off so `startServer.js`'s 10× poller does not retry.

## heartbeatRuntime

Left as-is. Still `NEXT_RUNTIME !== 'edge'` (the documented pitfall: requiring `=== 'nodejs'` silently disables heartbeats in the standalone Docker server). No module gate (core).

## Optional: single `platform_jobs` dispatcher

**Not implemented.** The pollers are not shaped for it:

- Different intervals (2s / 3s / 5s / 10min) and different “did work” signals.
- Two connector workers plus audit/rollout/rewrap/keepalive all talk to `platform_jobs`, but with distinct job types, lease namespaces, and side-effect graphs (S3, Vault, OAuth refresh).
- Two cleanups (`identityProviderTestAttemptCleanup`, `platformInstanceRegistryCleanup`) are not `platform_jobs` pollers at all — they use advisory locks.

A later design: one persistent scheduler at `min(interval)` that `SELECT … FOR UPDATE SKIP LOCKED` a bounded mix of types and hands each row to a type→handler map. Keep per-type `didWork` so idle backoff can still lengthen when the whole table is empty. Do **not** fold the two lock-based cleanups or the mihomo supervisor into that loop.

Idle backoff on the six hot pollers is the 80% win (11 timers × 2–5s → a handful of 60s ticks when the queues are empty).
