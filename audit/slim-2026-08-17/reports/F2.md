## Root causes found (E5's diagnosis was partly wrong — worth recording)

1. **The 8.1 MB `assets/es-*.js` is NOT "Shiki's full-language dep-map".** It is a shared vendor mega-chunk that the
   entry chunk imports **statically**. Composition, by sampling string literals across the file: `@lobehub/ui` +
   **`@lobehub/icons`** (megabytes of inline provider SVG paths, ~1.5→4.0 MB region), **`elkjs`**
   (`MODEL_ORDER_LEFT_TO_RIGHT`, `LayeredMetaDataProvider` — mermaid's ELK layout, only copy in the build),
   parse5/hast HTML utils, katex fragments, and **`@pierre/diffs`** (7 MB package, its own shiki copy with every
   grammar/theme — that is where the `__vite__mapDeps` of `abap`/`actionscript-3`/… comes from).
   Shiki proper is already lazy (`@lobehub/ui` does `import("shiki")`), and `@shikijs/langs/*` already build to
   per-grammar chunks — grouping them would have been actively harmful, so I did not.
2. **`i18n-ar` (0.91 MB of Arabic app copy) was statically imported by the entry** because `sharedManualChunks`
   merged `dayjs/locale/ar.js` into the app's `i18n-ar` chunk; dayjs' CJS core then landed in that chunk, and the core
   *is* on the entry's static graph. Same latent trap for every other locale.
3. **`i18n-src` (2.46 MB)** = all 53 default namespaces in one chunk, pulled in because `packages/locales/src/create.ts`
   statically imports 4 of them. Same for `i18n-en-US` (0.96 MB).
4. **`ErrorContent-*.js` 1.23 MB and `TagCloudCanvas-*.js` 1.01 MB are not what their names say.** `ErrorContent.tsx`
   is 80 lines; the chunk is just named after one member. `TagCloudCanvas` is 0.99 MB of **three.js** and was already
   `dynamic()` — it was only *preloaded*. So `React.lazy` on those two would have bought nothing; I fixed the
   preload/chunking instead.
5. `routeChunkPreload`'s `desktop-chat-launch` group walks dynamic imports transitively, so `index.html` preloaded
   basically the whole app — including **54 admin-console chunks (~1 MB)** that a normal user never opens.

# Round 2 (rework after `REVIEW_F2.out.md`)

## F1 (BLOCKER, rule 4) — done
- `plugins/vite/routeChunkPreload.ts`: `isAdminChunk` helper deleted; the admin path is now one entry in the
  existing `deferredRendererModulePatterns` list. Confirmed behaviour-identical — the rebuild produces the same
  127 eager / 107 idle file counts as the round-1 build.
- `InitializingState.tsx`: visibility state machine reverted. The original `setInterval` shape is back with a
  one-line guard (`if (document.hidden) return;`) inside the tick — 5 changed lines instead of 34.

## F2 (MAJOR) — investigated, root cause is upstream; documented instead of patched
The review assumed an `@lobehub/ui` Markdown/MDX → `CodeDiff` edge. There is none:
`grep -rl "CodeDiff" node_modules/@lobehub/ui/es` returns only `index.mjs` (the barrel) and `CodeDiff/*`.
The real edge is `@lobehub/ui/es/Highlighter/const.mjs`, which does a **static**
`import { bundledLanguagesInfo, bundledThemesInfo } from "shiki"`. The bundler co-locates that shiki metadata with
`@pierre/diffs`, so `vendor-diff` (0.45 MB) is dragged in eagerly by the Highlighter, not by any diff call site —
all six of ours already go through `@/components/LazyDiff`.

I spent the round-2 build testing the one fix available inside our code: a `vendor-syntax` group for
`shiki/dist/*.mjs` (metadata only, grammars excluded). **It regressed the bundle**: rolldown emitted a *second*
1.28 MB copy of the language/theme info tables while the first stayed in the shared chunk — eager JS went
21.78 → 22.97 MB. Reverted, with the measurement recorded as a comment in `sharedManualChunks` so nobody retries it.
Per the adjudication ("if it can only be done by patching the package, leave it and document"): removing this
0.45 MB needs an upstream `@lobehub/ui` change (lazy `bundledLanguagesInfo`), or a `patches/` entry.
