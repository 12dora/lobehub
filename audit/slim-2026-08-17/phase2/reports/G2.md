## Design as built

One `platformJobsDispatcher` owns a single `startPersistentWorkerScheduler` at `min(interval)` of the enabled types. Each tick: optional expired-`reserved` cleanup (runtime-audit journal), then `PlatformJobModel.claimBatch` (`SELECT … FOR UPDATE SKIP LOCKED`, `type IN (enabled)`, same pending | running-expired + attempt-budget dead-letter as `claimNext`), then per-row dispatch to the existing handler. A handler throw is logged and isolated. Any claimed row or reserved cleanup is `didWork` (whole-loop idle backoff resets).

Enable-set = boot-module view (`isBootModuleEnabled`) + Vault predicate for `secretRewrap`. Disabled module types are never in the `IN` list. The six worker names stay in `ENTERPRISE_WORKER_SPECS` as virtual specs so V1’s `[modules] worker … skipped` lines and `MODULE_BY_WORKER_NAME` stay intact; `start()` delegates to the dispatcher (`extraWorkerName` so `ensure*` still starts a loop when tests force `ENABLE_*=0`). Not folded: advisory-lock cleanups, branding GC, shared-OAuth keepalive, mihomo, GatewayService, readiness. No LISTEN/NOTIFY.

`claimNext` is unchanged. Rewrap jobs have `maxAttempts: null`; batch claim uses `statement_timestamp` (custom rewrap lane used `clock_timestamp`). Per-type lease TTL is applied on the UPDATE.

P6: `heartbeatRuntime` stays the ticker (edge predicate unchanged). Each tick opens one `db.transaction`: platform upsert + listeners. Each listener runs in `tx.transaction` (drizzle SAVEPOINT; available on this driver, verified on PGlite — no two-transaction fallback). The IdP listener rethrows after logging so only its writes roll back. IdP still starts a fallback 30s timer (boot order is IdP first); takeover clears it. Dev/test without the platform ticker keep the fallback.
