  F1 (codex said HIGH; VERIFIED MEDIUM): Global credential updates silently overwrite concurrent edits
     scope-correction: Codex overstates severity (HIGH→MEDIUM) and mis-scopes impact. The claimed security-sensitive scenario ("B submits an older form and silently reverts A's rotated secret TOKEN") cannot occur: platform-hosted secret values are never returned to or pre-filled in the edit form, empty secret fields are stripped client-side and treated server-side as "keep existing" (filterNonEmptySecretValues + the Object.keys(submitted).length > 0 guard), so a stale/passive submit leaves the secret untouched. The only reachable lost update affects non-secret metadata (name/description), and it requires two admins editing the same credential concurrently — real but low-consequence, not a HIGH security defect.
